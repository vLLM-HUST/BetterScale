# 前缀复用：我们需要证明什么

这不是另一个缓存实现。原生 vLLM/Ascend 已经负责 hash、物理页引用计数、
SWA 检查点、C4/C128 压缩页和 draft 状态。本轮增量是让 BetterScale 的
FULL target、TP draft 图与 DP 稳定 decode 路径接纳这些原生缓存命中。
不新增 monkey patch，不改命中算法；通过验收后移除原有关闭 APC 的准入限制。

## 命中不是“少算同样多的新 tokens”

12345-token 输入重复发送，实际复用12288，仅剩57个输入 token 需要推进；
修改第5000个 token 后，只能复用4096。当前默认物理页32，混合压缩状态
公共边界4K；不是每32个原始输入 token 都能形成完整可恢复检查点。
短公共前缀可能完全不命中，这是当前原生粒度，不是 FULL graph 的限制。

请求结束之后，缓存页仍可作为未引用的可回收缓存存在；后来的复用靠原生
hash 查找与引用计数，不复用前一个请求的陈旧 graph metadata。新请求先经过
原生准备，稳定 K5 波次才进入现有跨步优化。前缀改变时必须重新计算分叉后
状态，不能只看长度相同就复用。

## DP 的另一个条件：回到同一个 engine

DP 缓存是 engine-local。测试用原生 `X-data-parallel-rank` 请求头明确选择
engine，冷／热对照才能测试同一份缓存。普通负载均衡不保证请求回到原处；
真实 agent 服务仍需要上层会话亲和或缓存感知路由。这不是本轮插件新增的
全局共享缓存，也没有把八份池变成远程统一地址空间。

## 结果口径

TP 真权重32题原始检索：冷32/32、热32/32，全部热请求实际命中，全部
冷／热输出 token 一致。只代表保留的检索子集，不能扩写成完整质量认证。
Dummy 的分叉测试和延迟单独保留，不混入真权重速度成绩。

DP 真权重冷／热同样各32/32，全部热请求命中且输出一致。另有每rank两个
请求、共16路的8193-token输入重复队列，全部复用4096tokens。检查点需要
满足所有组的恢复条件，不能承诺命中长度总是简单向下取整到4K。
此前小预算抢占恢复失败不能靠本次“不发生抢占”的复用测试宣布修复。
